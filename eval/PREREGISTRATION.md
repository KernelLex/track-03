## Locked structural parameters (§17.6)

| Parameter | Value | Why |
|---|---|---|
| Population size (`n`) | **500** | Large enough for the per-arm recovered-fraction and violations counts to be stable to the eye at a 1-percentage-point resolution without being expensive to re-run; not fitted to any target precision, a structural choice |
| Random seed | **42** | Arbitrary, fixed so the run is exactly reproducible by anyone — `eval.personas.generator.generate_population` is deterministic given a seed, so this single number is the entire population |
| Window length | **30 days** | Matches the fitted `p_base` model's own horizon (`agent/decide/fitted_p_base.py`, fit against a 30-day payment-date target) — using a different window here would compare arms against a probability the fitted model was never evaluated at |
| Primary touch cost | **Rs 5** (`DEFAULT_TOUCH_COST_PAISE`) | The realistic cost of a message-based touch (Telegram, effectively free; a nominal Rs 5 placeholder per `agent/orchestrate.py`'s own default) — the honest, un-stress-tested economics this project actually runs on |
| Primary `lift_prior` | **1.0 (neutral — no assumed uplift)** | The most defensible point in the declared 0.5x-4.0x sweep range: not assuming an instrument/message converts any better or worse than baseline, so any Arm C advantage at this point comes from diagnosis routing and bounds discipline alone, never from a favourable assumption about the one parameter with no empirical source (§17.1) |

## Primary comparison (§17.6)

**Recovered fraction, Arm A vs Arm C, at the locked parameters above.**
Chosen over a comparison at a swept, assumed-favourable `lift` specifically
*because* it needs no assumed behavioural uplift to be interesting — Law
II in a different register: the primary claim shouldn't rest on a value
nobody can source. Reported alongside, not instead of: Arm B2 at the same
point; the real `check_bounds()` violations count per arm (§17.7's
"violations column" — computed as a shadow check, `eval/simulate.py::
_shadow_bounds_violation`, since this harness's B2/A touch model has no
literal mandate/AFA action to check against, only a real, triggerable
`DISPUTE_FREEZE` case); the Family-B-only breakout (§17.7, §26.1); the
break-even sweep of `lift_prior` over the full declared 0.5x-4.0x range at
both the primary (Rs 5) and a stress-tested elevated (Rs 20,000) touch
cost, since the primary cost was found, while building this, to make
`lift` structurally non-binding (EV_FLOOR never refuses regardless of
`lift` at Rs 5 against this population — a real, reported finding, not a
methodology error); and the decision-flip-rate under ±50% perturbation at
both costs.

## Arm definitions (§17.4)

| Arm | Definition | Status |
|---|---|---|
| **A** | Fixed standard dunning schedule, no model | **Built and implemented twice**: `eval/arms/a/schedule.py` is the real fixed-day schedule; `eval/simulate.py::run_arm_a` drives it against a synthetic population with no diagnosis and no bounds gate. |
| **B1** | LLM chaser, no policy in the prompt, no gate | **Not implemented, by design** — this file's own "cut B1, never B2" guidance below, applied. A live LLM call now exists (`agent/diagnose/llm_extract.py`) if this is ever revisited, but the Monte Carlo harness deliberately spends its effort on B2 and C instead. |
| **B2** | LLM chaser, the human-readable twin from `agent/bounds/rules.yaml` verbatim in the system prompt, no enforcement gate | **Simulated in the harness** (`eval/simulate.py::run_arm_b2`) without a live call per touch — it stands in for "knows the policy, nothing enforces it" via a diagnostic-accuracy draw with no bounds gate, so it can still over-contact past a debtor's tolerance. The real system-prompt text is mechanically extractable now (every rule's `human:` field) for a future live-B2 variant; the harness's current B2 is the cost-free statistical stand-in, not that live call. |
| **C** | TrueCommit — same policy text, enforced by `check_bounds()` | **Both sides now built and wired together in the harness.** `eval/simulate.py::run_arm_c` calls the real `compute_ev()` and `check_bounds()` per touch (only Diagnose is simulated, via a diagnostic-accuracy draw — there's no real text to extract from a synthetic persona). `p_base` is the real fitted model (`agent/decide/fitted_p_base.py`). |

**If room for only three arms, cut B1, never B2** (§17.4) — noted here so
the harness, once built, doesn't relitigate that call.

## Metric set (§17.7)

Tier 1 metrics that need no eval run are already reported where they're
produced, not deferred to `RESULTS.md`:

- Rail conformance (`agent/rails/conformance/suite.py`, passing against both rails)
- Idempotency (shuffled-thrice, `tests/agent/test_shuffled_replay.py`)
- `check_bounds` twin agreement (5,000-input differential test, `tests/agent/test_bounds_differential.py`)
- Ledger replay + tamper detection (`docs/LEDGER.md`, generated with real output)
- Injection resistance (`tests/agent/test_injection_resistance.py`, 80 tests — structural, not empirical; see docs/THREAT_MODEL.md)

Metrics that need an eval run and are **not yet available**: extraction
field-level F1, family classification macro-F1, objection-veto recall with
Wilson intervals, `p_base` calibration against a real (not synthetic)
outcome, autonomy rate, abandonment by invoice-size decile, simulator
response-rate error bar (§27) — all of these need either a real golden set
of labelled extractions or a real arm run against real debtors, neither of
which exists.

**Now available from the synthetic Monte Carlo harness** (`eval/simulate.py`,
not yet run for a pre-registered comparison — see the status note above):
recovered fraction, resolved fraction, mean days to resolution, human
escalation rate, and contact-exhaustion ("lost") rate, per arm, over a
reproducible synthetic population. Decision flip rate under `lift`
perturbation is now genuinely exercisable too — `run_arm_c` calls real
`compute_ev()` per touch, so `agent.decide.ev.decision_flips_under_
perturbation` can be run against the `(p_base, lift)` pairs a harness run
actually produces, not just unit-tested in isolation. None of this is a
substitute for the real-debtor metrics above — it measures whether the
*pipeline's logic* helps a population with known (synthetic) ground truth,
not whether real extraction is accurate.
